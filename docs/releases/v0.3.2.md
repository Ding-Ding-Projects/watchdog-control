# Watchdog Control v0.3.2

This release adds native Windows hosting to the portable setup assistant, alongside its existing Docker Compose route. The native controller, Node.js monitor and pinned cloudflared executable are bundled into the setup file.

## Hosting and temporary access

- Choose native hosting when Docker is unavailable, or use the published container image and tracked Compose files.
- Opt into a free temporary Cloudflare Quick Tunnel. The monitor verifies HTTPS health, management assets and sign-in protection before displaying an address.
- Recover interrupted tunnels with bounded backoff and verify each replacement address.
- Store an optional Discord webhook through the protected local field. Notifications contain verified addresses, never pairing codes or webhook values.
- Start the monitor and selected service when the current user signs in. Automatic sign-in and machine-wide startup settings are not changed.

The Windows certificate loader uses a temporary current-user key compatible with Schannel. The wizard performs endpoint verification through its fixed bundled Node client, preserving strict certificate and hostname checks and existing trust material.

## Delivery boundaries

Real native HTTPS, authentication rejection, tunnel replacement and startup registration were verified during this work. A new sign-in or reboot was not performed. Discord delivery requires an operator-configured destination. Docker runtime verification remains unavailable on the selected Windows host. The live chat-style PowerShell/CMD terminal is a separate design and implementation handoff in [issue #3](https://github.com/Ding-Ding-Projects/watchdog-control/issues/3), not an implemented feature in this release.

## 廣東話摘要

設定精靈新增毋須 Docker 的 Windows 原生託管，連控制器、監察程式同臨時通道工具一齊隨附。通道地址要先通過 HTTPS、管理畫面資源同登入保護檢查先會顯示；中斷後會有限度重試，再驗證新地址。Discord 目的地要由使用者喺受保護欄位設定。登入啟動只影響目前使用者，唔會修改自動登入或重新啟動電腦。即時聊天式終端仍然係獨立設計交接，未喺呢個版本實作。
