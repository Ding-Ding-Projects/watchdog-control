# Watchdog Control v0.1.1

This release updates the portable setup assistant and host controls for Watchdog Control. It includes the authenticated dashboard, typed LAN API, Windows host agent, tracked container deployment, and release-bound configuration files.

## Setup assistant and hosting

- `WatchdogControlSetup.exe` is a self-contained single-file setup assistant that can be launched without installation.
- The assistant embeds `compose.yaml` and verifies its SHA-256 against the release manifest before using it.
- Exact existing setup files are reused. Differing local configuration requires confirmation and verified byte-for-byte backups before replacement.
- The welcome screen offers one-click local hosting when a local Docker Engine and Compose plugin are ready, the selected private LAN address and HTTPS port are usable, the saved data location is clear, and a verified release manifest is available.
- The one-click route pulls the immutable image and starts only the Watchdog Control service. It does not install Docker Desktop or the optional Windows host agent.
- The guided setup remains available for supported prerequisite installation, storage selection, consent, and recovery.
- Double-clicking `host.bat` starts or updates the service after an eight-second selection timeout. `host.bat --detached`, `host.bat --logs`, and `host.bat --stop` are also supported.

## Release files

- `WatchdogControlSetup.exe` is the portable setup assistant.
- `watchdog-agent-win-x64.exe` is the optional Windows host agent. Installing the machine-wide service requires explicit operator consent and native administrator approval.
- `watchdog-control-image-linux-amd64.tar` is the image archive. The image is also published by immutable digest.
- `compose.yaml`, `host.bat`, `host.ps1`, and `default.env.example` provide the deployment files and credential-free configuration sample.
- `watchdog-release-manifest.json` binds the source commit, version, immutable image digest, image archive hash, Compose hash, service paths, and health endpoint.
- `SHA256SUMS.txt` contains the checksums for the release files other than itself.

The Windows files are unsigned. Windows may show an unknown-publisher warning. No signature or authenticity claim is provided.

## Verification limits

The release workflow builds and packages the Windows files, publishes the image, verifies the release tag and download bytes, and deploys the documentation download card from the verified release. It does not run automated tests or lint. Release publication does not establish that a host was installed, that a client can reach the service over a LAN, or that a host operation was exercised.
